Concurrencia y Transacciones: Garantías ACID

Integridad de órdenes mediante Checkout Atómico, Snapshot de Precios y Rollbacks automáticos.

Integridad Atómica en Checkout

Snapshot de Precios & Vaciado Indivisible

En e-commerce, los cambios de precios o fallos de red durante el checkout pueden generar discrepancias de facturación o carritos inconsistentes si no se asegura atomicidad transaccional completa.

Transacción de Sesión SQLAlchemy: GARANTÍA ACID
1. Apertura de transacción con sesión atómica
2. Creación de instancia Order en estado PENDING
3. Snapshot inmutable de precio histórico por OrderItem
4. Vaciado coordinado de líneas en CartItem
5. Commit indivisible o Rollback total ante excepción
Solución TryOn Hub: OrderRepository ejecuta la conversión atómica y congela el precio histórico.
# Checkout Atómico & Snapshot de Precios (commerce_repository.py)
def create_from_cart(self, db: Session, user_id: int, cart: Cart) -> Order:
  """Transacción ACID: congela precios y vacía carrito atómicamente"""
  order = Order(user_id=user_id, total_amount=0.0, status=OrderStatus.PENDING)
  db.add(order)
  db.flush()

  total = 0.0
  for item in cart.items:
    price = item.garment.price if item.garment else 0.0
    order_item = OrderItem(
      order_id=order.id, garment_id=item.garment_id,
      price=price, quantity=item.quantity,
      size=item.size, color=item.color
    )
    total += price * item.quantity
    db.add(order_item)
    db.delete(item)

  order.total_amount = round(total, 2)
  db.commit() # Atomic commit: confirmación íntegra o rollback
  return order

# Implementación del Patrón Observer Push (job_observers.py)
class JobSubjectMixin:
  def __init__(self):
    self._observers: List[IJobObserver] = []

  def register_observer(self, observer: IJobObserver) -> None:
    if observer not in self._observers:
      self._observers.append(observer)

  def notify_observers(self, old_status, new_status, context=None):
    for observer in list(self._observers):
      observer.update(self.id, old_status, new_status, context or {})

CRIPTOGRAFÍA & RBAC 10 / 13

Seguridad y Criptografía: Bcrypt & RBAC

Protección robusta de credenciales, autenticación stateless JWT y autorización por roles.

Bcrypt Hashing

Salting y factor de trabajo adaptativo

Implementado mediante Passlib CryptContext(schemes=["bcrypt"]). Resistencia computacional demostrada contra ataques de fuerza bruta y diccionarios con GPU.

Stateless JWT Auth

Tokens firmados criptográficamente

Tokens firmados con algoritmo HMAC-SHA256 (HS256), portando claims estándar (sub, exp, iat) y validación en cada request con OAuth2PasswordBearer.

Role-Based Access (RBAC)

Roles: Admin, Brand Manager, Customer

Aislamiento por roles en base de datos: Platform Admin, Brand Manager y Customer. Control de acceso que impide que clientes editen catálogos o marcas modifiquen órdenes ajenas.

Recuperación Segura de Contraseña (Single-Use Token)

Token temporal con expiración de 30 minutos (PASSWORD_RESET_EXPIRE_MINUTES: 30) y huella criptográfica SHA-256 (pwf) del hash actual. Al restablecer la contraseña, el hash cambia e invalida inmediatamente cualquier token previo, evitando ataques de repetición.
